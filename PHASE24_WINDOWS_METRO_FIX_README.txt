PULSECHAT PHASE 24 — WINDOWS METRO RESOLUTION FIX
=================================================

Issue
-----
On Windows, `npx expo start -c` could fail while bundling Web with:

  Unable to resolve module @noble/ciphers/aes

Cause
-----
The locked @noble/ciphers 1.3.0 package exposes AES and utility modules through
package subpaths. The affected Windows Metro installation did not resolve
either the extensionless or explicit .js package subpath even though Node and
the Linux Metro release gate resolved both.

Fix
---
The app no longer asks Metro to resolve a noble-ciphers package subpath.
The required audited AES-GCM and encoding functions are bundled into:

  src/vendor/noble-ciphers-runtime.js

secure-envelope.js loads that local relative file. The exact generated bytes
are SHA-256 locked in the release baseline, the build command runs before the
Phase 24 gate, and the upstream MIT license is retained beside the bundle.
Encryption format and existing encrypted data remain compatible.

Verify on Windows
-----------------
1. Stop Metro with Ctrl+C.
2. Extract the corrected Phase 24 package into a clean directory, or replace
   the changed files.
3. Run:

     npm ci
     npx expo start -c

4. Press `w`. Web must bundle without the noble-ciphers resolution error.
5. Test Android from the same corrected dependency installation.

JWT clock warning
-----------------
If Web reports `JWT issued at future`, synchronize Windows Date & time, close
all PulseChat tabs, clear the localhost session storage, and sign in again.
This warning is caused by clock/session skew and is separate from Metro.
