# Phase 24 release engineering report

## Outcome

The PulseChat Prototype V1 source is prepared as a reproducible Android release
candidate. Release identity, asset bytes, local versioning, EAS profiles,
Firebase file injection, remote signing policy, generated native resources,
and clean-package verification are now explicit and testable.

The source is **ready for the owner EAS build and device QA**. This report does
not claim a signed APK was produced: the implementation environment had no EAS
login/token or Android SDK. The owner must run the documented EAS build and
sign the Phase 24 acceptance record.

## Verification record — 2026-08-29 UTC

- `npm run qa:phase24`: passed.
- TypeScript, ESLint, secret scan, 18/18 unit tests, Phase 22 source preflight,
  Phase 23 accessibility audit, Phase 24 release audit, source-only native
  Android prebuild, Android export, and Web export: passed.
- `npm run release:gate:configured`: passed against the owner-supplied local
  `.env` and `google-services.json`; neither file belongs in the handoff ZIP.
- Runtime dependency high/critical gate: passed. npm reported 11 moderate
  advisories in the Expo native configuration toolchain; the suggested forced
  changes are SDK-breaking and were not applied to this locked Phase 24
  candidate.
- Signed preview build: blocked before upload because no Expo account or
  `EXPO_TOKEN` was available. No build artifact was claimed.

## Windows Metro correction

Owner testing exposed a Windows Metro resolver failure for both extensionless
and explicit `.js` `@noble/ciphers` package subpaths. Phase 24 now bundles only
the required audited AES-GCM/encoding runtime into a local source file, retains
the upstream MIT license, and locks the generated bytes in the release audit.
Metro therefore resolves a normal relative project file instead of a package
subpath. This does not change the AES-256-GCM envelope format or stored-data
compatibility.

## Queued-message database correction

Owner Web testing reached the backend and exposed PostgreSQL's
`column reference "actor_user_id" is ambiguous` error in the Phase 21 private
rate limiter. The original function used the same name for an input parameter
and the primary-key column in an `ON CONFLICT` target. The Phase 24 forward
migration preserves the function ABI and privileges, uses positional parameters,
and targets `rate_limit_state_pkey` by name. `supabase/phase24_verify.sql`
checks the definition, private privilege boundary, initial insert, and conflict
update path.

## Fixed release risks

- The generic Expo launcher/splash art was replaced with PulseChat-specific,
  reviewed assets for legacy, adaptive, monochrome, splash, notification, and
  Web use.
- Android versionCode is explicit and source-controlled rather than delegated
  to remote auto-increment state.
- EAS CLI and the npm dependency graph are pinned.
- Release profiles have unambiguous APK/AAB outputs, environments, distribution,
  and remote credential ownership.
- Release builds fail closed if Firebase client configuration is absent.
- The ignored local Firebase file can be injected into EAS as a secret file
  variable, preventing it from entering source archives.
- The clean-source audit locks application ID, version, project ID, permissions,
  notification channel, profile behavior, and reviewed asset hashes.
- A temporary native prebuild verifies the generated Gradle/manifest/resource
  state without committing an Android native directory.

## Boundary

Phase 24 remains inside the Prototype V1 release boundary. It adds one
forward-only corrective database migration for the existing private limiter,
not a new product feature. Play Console submission remains Phase 25;
crash/latency telemetry and push-receipt operations remain Phase 26.
